# AI Tooling Monitor

The 8th portal (`tooling/*`, migration `0054`): a weekly market scanner for AI tools, built for an AI-transformation team at a large regulated financial-services company. Public catalog, keyholder (portal) extras, admin console.

Full write-up: docs/tooling-monitor.md

## Pages and access
- `tooling/page.tsx` (public): FTS + facet search over the catalog, "New this week", cataloged products by category. Portal keyholders also see held-for-review (parked) products, the agent read and an add form.
- `ToolingInfo`: round "i" button beside the title (funnel, reading a card, who sees what, reports); uses the `.fb-overlay`/`.fb-card` dialog idiom.
- Mono cadence line under the lede from `getToolingRuns(1)`: last scan day, found/cataloged, next Monday 07:00 UTC.
- Filter plate `.tl-filters`: one toolbar row, search + a `<select>` per facet navigating on change via `router.push`, "Clear all". Category headings in the grid link to `?category=`.
- `ProductLogo` (client): Google's favicon service by `vendor_domain`/URL host, a GitHub owner avatar for repo-hosted projects, a hashed-hue monogram tile on failure. Nothing stored.
- The "New this week" strip never hides: fixed 260px cards, 3-line clamp, right-edge fade, empty copy, entrants-report link in its head row.
- Count line: "N cataloged products across M categories" or "N of M products match" (`countCataloged`). Card meta is ` · `-joined with "first seen" (the scanner date, not founding). Fit chip carries a rubric tooltip.
- `[slug]` pages get `generateMetadata`, breadcrumb links, and `humanize()`d compliance/integration/model tags.
- `dateLabel` formats bare `YYYY-MM-DD` in UTC (run days and week-endings render a day early in US zones otherwise).
- `tooling/[slug]/page.tsx` (public once cataloged, `maxDuration = 120`): facts, features, dossier, agent read + deep dive (portal), events, siblings. Admin curation/facts/tools.
- `tooling/reports/page.tsx` (portal, inline unlock, `maxDuration = 120`): guests see the published shelf above the unlock. Unpublished tooling reports are readable by keyholders.
- `tooling/console/page.tsx` (`adminGate`, `maxDuration = 60`): engine tick loops (this week's run + the big pull), prefs (thresholds, deep-dive cap, auto-publish entrants, models, steering, editable rubric), category registry, curation queue, runs/health/spend, datasets + handoff, model A/B.
- Styles `.tl-*` in `app/styles/tooling.css`.

## Table view (`tooling/table/page.tsx`, public, the "Table" tab)
- Every cataloged product in a sortable, filterable table: `components/tooling/ProductTable.tsx`; pure `lib/tooling/table-core.ts` holds rows, columns, comparators, matching. `ProductFilters` takes a `base` prop.
- 50 per page, column chooser, free-text row filter, compare strip for 2-4 selected rows (feature union).
- Quick-read drawer per row (`ProductQuickRead`): facts, features, agent read for portal/admin, last 5 events from the public `GET /api/tooling/events?product=`.
- CSV via the datasets route: `tooling-catalog` for guests, `tooling-products` for keyholders.

## Reports
- Four kinds on `generated_reports`: `tooling_landscape`, `tooling_brief`, `tooling_entrants`, `tooling_features`. Generated by `lib/tooling/reports.ts` (two Sonnet legs, citation-gated).
- The brief's `internal.ourContext` renders only for admin/portal.
- The weekly entrants report is auto-published (the second auto-publishing kind).

## Engine (`lib/tooling/engine.ts`)
- The intel pattern on `tooling_runs` keyed `(kind, day)`; weekly day = the Monday UTC.
- Stages: discover → hydrate → enrich → score → finish → events → deepdive → report → complete.
- discover: `cat:<slug>` = Tavily + HN + GitHub → cheap-model triage → `insertProducts` dedupes on `url_key` else `name_key` + `vendor_domain`; `ph`; pull-only `enum:<slug>:<leaders|emerging>` Sonnet web-search enumeration.
- enrich: GLM-5.3-flash default.
- score: qwen flash, the rubric: fit 0-100 + five 1-5 dims + `steal`. Candidate → cataloged at `catalog_threshold` else parked. Never demotes, never touches pinned.
- finish: pricing page + feed discovery. events: vendor feeds.
- deepdive: `dd:<id>`, Sonnet web_search x3, high-fit entrants, capped.
- report: weekly entrants report.

## Crons and budgets
- `/api/cron/tooling` Mon 07:00 UTC, `/sweep` 08:20, `/sweep2` 17:00. `?kind=pull` advances a console-started pull headlessly.
- Per-run budget sums `ai_cost_log` rows carrying `metadata.tooling_run`: `TOOLING_WEEKLY_BUDGET_USD` (4), `TOOLING_PULL_BUDGET_USD` (12).
- Optional env: `PRODUCTHUNT_TOKEN` (its API terms restrict commercial use; unset = source skipped), `GITHUB_TOKEN` (raises search rate limit), `HC_PING_URL_TOOLING`.

## Data and guest safety
- Categories: the real list seeds from the untracked `private/tooling-categories.json` via `db:seed:tooling`.
- Datasets: key-gated `tooling-products`/`tooling-events`/`tooling-features`, public `tooling-catalog`.
- Guest safety: `PRODUCT_PUBLIC_COLUMNS`/`PORTAL`/`ADMIN` column lists in `lib/data/tooling.ts`. Agent fields are portal + admin only.
