# The AI Atlas

## What this is
A **single-user tool for staying oriented in the AI-economy debate**, with **two public surfaces over one body of material.** The **Argument Map** (`/map`) maps *where the disagreement actually is*: open questions, candidate stances, the falsifiable claims they stand on, the bridge-claims that link domains, and the evidence. The **Signal Board** (`/signals`) is a feed of tracked AI developments, sorted by audience lens and wired back to the claims they touch, fed by an admin **discovery pipeline** (`/pipeline`). A private **personal layer** (confidence, rationales, source priors) sits on top of a public **share view**. The goal is **orientation, not proof** — the model proposes, the human commits. Design docs live in `docs/`.

## Architecture & conventions
- **All DB access is server-side.** `lib/db.ts` owns a global `pg.Pool` connecting as a role that **bypasses RLS**. The *server* decides public (the map) vs. personal (confidence, rationales, priors). `lib/db.ts` throws if imported in the browser. Helpers: `q()`, `one()`, `exec()`, `withTx()`. Never import `lib/db` into a client component.
- **numeric is parsed as a JS number.** `lib/db.ts` calls `pg.types.setTypeParser(1700, (v) => parseFloat(v))` so confidences (Postgres `numeric`, OID 1700) arrive as numbers, not strings — they're used in sliders / `toFixed`. (Note: `date`/`timestamptz` still come back as JS `Date` objects — cast to text in SQL, e.g. `to_char(...)`, when a string is needed.)
- **Admin/Guest gate** (`lib/auth.ts`): admin session is a **signed HMAC cookie** (`atlas_admin`, value `admin.<hmac>`); guest is a non-privileged UX flag (`atlas_guest`). `secret()` **fails closed** — throws if `AUTH_SECRET` is missing or `< 32` chars (no public fallback that could be forged). `isAdmin()` is the real security boundary (verifies the signature with `timingSafeEqual`); `checkPassword()` compares fixed-length HMAC digests via `timingSafeEqual` and returns false if `ADMIN_PASSWORD` is unset. `isPreview()`/`isEditMode()` are unsigned admin-only UX flags; `shareToken()`/`verifyShareToken()` back the public `/share` link. `proxy.ts` only does **cookie-presence routing** (no `atlas_admin`/`atlas_guest` cookie → redirect to `/login`, except the public allow-list: `/`, `/blotter`, `/login`, `/share`, `/about` + `/about/*`, `/signals` + `/signals/*` (except `/signals/new`, `/signals/digest`, `/signals/drafts`, `*/edit`), `/reports` + `/reports/*`, `/research` + `/research/*` (except `/research/digest` and `/research/console`), the three redirect stubs (`/landscape`, `/lens`, `/supply-chain`), the unlisted `/showcase` deck, `/api/ask/doc` (isPortal-gated in-route), `/api/tickets` (the public feedback intake, fully validated in-route), `/api/cron/*` (the scan/pipeline/intel cron drivers + their `/sweep` siblings; each enforces `Authorization: Bearer CRON_SECRET` in-route, failing closed when unset), and the **public reader surface** — `/map`, `/bridges`, `/bridge/*`, `/concepts` + `/concepts/*` (except `/concepts/new` and `*/edit`), `/claim/*`, and `/q/*` except `/q/*/summary` — which all render the guest/share view (personal layer stripped server-side via `personal = isAdmin() && !preview`) without a session, so a managed-network visitor is never bounced to the phishing-flagged `/login`); it is *not* authorization.
- **Personal layer stripped server-side** (`lib/data/*`, barrel-imported as `@/lib/data`; the strippers live in `lib/data/shared.ts`): `strip()` nulls `confidence`/`confidence_label`; `stripClaim()` additionally nulls `domain_note`; `getEvidenceFor()` nulls `reliability_prior`/`note` for guests; `getQuestions(personal)` zeroes `contested_count` and nulls `last_moved`; rationales are returned only for admins. **Guest mode IS the share view** — there is no separate share renderer. On the Signal Board, guests see only **published** signals (drafts are admin-only); a touched claim's confidence word and the model's per-touch **reason** (`signals.touch_details`) are admin-only, while a touch's **direction** is descriptive and shown to all. `resolveTouches` flags unresolved codes for admins (drift guard).
- **Server actions** (`lib/actions/*`, one `'use server'` module per domain plus a directive-less `index.ts` barrel and a `shared.ts` for the guards/parsers — never re-export or client-import `shared.ts`): every action calls `requireAdmin()` first and validates input (allow-listed enums, prior 0–100, confidence 0–1, `UUID_RE`, `safePath()` blocks open redirects). They call into `lib/mutations/*` (the only writer, barrel-imported as `@/lib/mutations`) and `revalidatePath('/', 'layout')`. (Some AI actions are typed-arg and return data to the client rather than redirecting — e.g. the pipeline step actions and the manual signal flow's `prepareSignalFromSourceAction`/`overrideAndApproveAction`.)
- **AI integration:** **most** AI features — source dossier, PDF metadata auto-fill, claim recommendations (recommend-only), lens recommendations, concept prerequisite/claim-wiring recommendations + the concept gap diagnosis (`lib/concepts.ts`, recommend-only), the argument-map gap diagnosis + claim/bridge edge recommendations (`lib/argument-gaps.ts` / `lib/argument-nodes.ts`, recommend-only), question-state summaries, and Signal Board draft proposals — route through `runStructured` in `lib/dossier.ts`: a single forced-tool, **non-web** Anthropic call (`claude-sonnet-4-6`, thinking off, effort low/medium per caller) returning validated JSON. `lib/summary.ts` reuses it (metrics computed in code, the model only narrates). The web-enabled paths are the discovery pipeline, scout discovery (`lib/scout/web.ts`, same call shape), and the /ask web toggle; the pipeline's primary (`lib/pipeline/web.ts` `searchCandidates`): a standard `messages.create` with the GA `web_search` tool (`web_search_20250305`, no beta header) plus a `submit_candidates` client tool. To fit Vercel's hard ~60s cap it is **decomposed into many short, DB-checkpointed units** (one lens's query batch, ≤3 searches ≈ 45s), not one long call; the analysis step is likewise **two invocations per candidate** — `hydrateCandidateAction` (fetch + cache `raw_content`, with the reader fallback) then `analyzeCandidateAction` (the model leg). Discovery passes `blocked_domains` (curated deny-list + learned zero-yield domains — guardrails in `getZeroYieldDomains`: duplicates count as YIELD, a never-auto-block allowlist protects primary sources/wires, and only the trailing 90 days count so blocks can decay) to the search tool, and the run-static prompt halves (analysis target list, triage digest) live in the cached system block. Two more web-enabled units per run (the Kimi-K3-miss fixes): the **breaking-events sweep** (`searchBreakingSweep` — lens-agnostic, significance-first, over a curated `allowed_domains` outlet list; every entry must be crawlable by Anthropic's agent or the API 400s — reuters/apnews/nytimes/wsj/ft/economist/theverge/arstechnica all block it) and the **post-run coverage check** (`lib/pipeline/coverage.ts` — re-derives the window's biggest AI developments with independent phrasing, marks each covered/missed vs. the run's candidates + existing signals, persists to `pipeline_runs.coverage`, advisory only). Lens query templates resolve `{year}` AND `{month}` from the run window (`resolveDateTokens`) — month-anchored, news-shaped phrasing, because evergreen year-only queries surfaced SEO listicles instead of the week's news. Triage carries a **materiality override** (a major uncovered development gets approved even from a weak source). Requires server-only `ANTHROPIC_API_KEY`.
- **The human gate** (`moveConfidence` in `lib/mutations/core.ts`): transactional via `withTx` — it reads the old confidence, updates it, inserts a `rationales` row (a **rationale is required**; `actions.ts` rejects empty, and the move may optionally cite an `evidence_id` surfaced in `ConfidenceEditor`), and auto-writes a `post_commit` **snapshot** of all confidences (claims, stances, bridge_claims, and `positions_crosscutting`) — all atomic. A confidence can never move without its "why". Both the discovery pipeline and the manual *Turn into signal* flow mirror this gate: each only ever creates a **draft** signal (through the shared `analyzeCandidate` → `createDraftForCandidate`); a human publishes. **Publishing a signal is itself a gate**: `setSignalPublished`/`createSignal`/`updateSignal` call `syncSignalEvidence` (transactional) which materializes one **evidence** row per touched claim/bridge (carrying `signal_id`, `lens`, `direction`, and the reason as excerpt) — so a signal's findings enter the Argument Map only on publish, and unpublish/delete removes them.
- **Confidence: stored as `numeric(3,2)` 0–1, displayed as a word.** A generated column `confidence_label` (Postgres `conf_label()`) maps it: `<0.40 thin`, `<0.60 contested`, `<0.80 leaning`, else `settled`. `components/ConfidenceEditor.tsx` mirrors these thresholds client-side for the live preview. Words/colors are rendered via `lib/format.ts`.
- **Dynamic rendering:** every page that reads cookies/DB sets `export const dynamic = 'force-dynamic'`. Pattern in public pages: `const admin = await isAdmin(); const preview = await isPreview(); const personal = admin && !preview; const data = await getX(slug, personal);`. Admin-only pages (`/ingest`, `/source/[id]`, `/sources`, `/q/[slug]/summary`, `/pipeline`, `/worldview`, `/data`, `/calibration`, `/costs`, `/reports/period`, `/tickets`, `/signals/new`, `/signals/[id]/edit`, `/signals/drafts`, `/signals/digest`, `/scan`, `/intel`) instead gate with `const admin = await requireAdminPage();` (`lib/auth.ts`; redirects non-admins to `/login`, returns `true`) as their FIRST await — never an inline `isAdmin()` + `redirect` pair; `/signals`, `/signals/[id]`, and `/reports/[id]` are **public**. Routes that host an AI server action set `export const maxDuration = 60` (`source/[id]`, `ingest`, `q/[slug]`, `q/[slug]/summary`, `pipeline`, `reports/period`, `research/*`, `scan`) — page-level `maxDuration` covers its server actions. The one cron route, `/api/cron/scan`, sets `maxDuration = 300` and gates on `CRON_SECRET`, not the admin cookie.
- Path alias `@/*` → repo root.

Later migrations also add eleven tables: `dedupe_scan` (`0010`), `reports` (`0011`), `ai_rate_cards` + `ai_cost_log` (`0014`), `0017`'s **concepts trio** (own bullet below), `concept_gap_scan` (`0018`, the persisted gap-diagnosis singleton), `0019`'s supply-chain pair (`supply_chain_node_meta` + `supply_chain_node_signals`), and `argument_gap_scan` (`0021`, the persisted argument-map gap-diagnosis singleton — the AI-proposed claims/bridges a human commits via the add-node authoring forms). RLS is **enabled with no public policies** on every table (deny-by-default; the app's DB role bypasses — all access is server-mediated).
- **`edges`** is the polymorphic argument graph: `(from_type, from_id) → (to_type, to_id)` with a `relation` (`supports`/`contradicts`/`depends_on`/`organizes`), `*_type ∈ {stance, claim, bridge_claim}`. Claims attach to **stances** and to **bridge_claims** through edges; stance↔stance "contradicts" edges encode the strongest-opposing guardrail.
- **`claims`**: a claim requires a `test` and a `domain` unless `is_frame=true` (check constraints `claims_test_required` / `claims_domain_required`). **Frames are claims with `is_frame=true`** (no domain/test/confidence) — they `organizes` other claims via edges and are quarantined from evidence.
- **`bridge_claims`** are **first-class** inter-domain objects (`domain_from`/`domain_to`, own `test`/`confidence`), not edges.
- **`evidence`** targets a `claim` or `bridge_claim` (polymorphic `target_type`/`target_id`) and carries its provenance via `source_id` (manual ingest) and/or `signal_id` (materialized from a published signal) — **both nullable, CHECK requires at least one** (`0006`). It also carries an optional `lens` (`signal_lens_t`, the audience lens the finding speaks to). `signal_id` is `on delete cascade` (a finding dies with its signal); `source_id` stays `on delete cascade`. The two writers `addEvidence`/`addEvidenceMany` are source-anchored (manual); `syncSignalEvidence` is signal-anchored (publish-time). Sourceless signal evidence (`source_id` null) shows on claim pages and feeds rollups but is excluded from the source-centric views (`getEvidenceGraph`/`getLandscape`).
- **`content_blocks`** (`0003`) — per-key text overrides for the About/landing copy (admin inline edit-mode; `atlas_edit` cookie). A missing key falls back to the code default.
- **`signals`** (`0004`) — the public Signal Board feed: a tracked development with `significance` (`significance_t` high/medium/low), `lenses` (array of `signal_lens_t`: `market`/`labor`/`geopolitics`/`regulatory`/`capability`/`society` — a **separate, audience-tailored enum** from the map's `lens_t`), `claim_touches` (a `text[]` of claim/bridge codes carried **on the row**, not a join table — resolved at read time, GIN-indexed for the reverse "signals touching this claim" query), **`touch_details jsonb`** (`0006`; `{code: {direction, reason}}` — the draft-stage detail the admin reviews, materialized into `evidence` on publish), a soft `source_id` ref, `published_at` (editorial date — drives ordering + the digest range) vs. `is_published` (visibility gate; guests see published only; **publish also materializes evidence** — see the human gate), and `origin` (`signal_origin_t` manual/pipeline, for the pipeline badge). **`digest_snapshots`** (`0004`) is the audit log for the not-yet-built digest sender.
- **Discovery pipeline** (`0005`): **`pipeline_runs`** tracks one run — `status` (`run_status_t` running/completed/failed), `step` (`run_step_t` discovery/triage/analysis/complete), `cadence` (`run_cadence_t` manual/daily/weekly/**`source`** — the last for single manual-source runs, kept out of the discovery history/analytics/lookback), running tallies, and (`0026`) `coverage jsonb` — the post-run coverage-check audit (`{since, checked_at, developments:[{headline,url,covered,matched}]}`). **`signal_candidates`** holds items to triage — `lens` (reuses `signal_lens_t`), `triage_status` (`triage_status_t` pending/approved/rejected/duplicate), `unique (run_id, url)` dedup, cascade-delete on `run_id`, a `signal_id` set when a candidate becomes a draft, and (`0015`) a `source_id` set when the candidate is a **manual upload** (so analysis reuses the curated source's text/metadata/prior instead of `ensureSource`'ing a bare row). Triage also flags any discovered URL already present in `sources` (a manual upload) or a prior draft as `duplicate`, so a manual link never re-enters discovery. These tables ARE the run's checkpoint state (so runs are resumable). Pipeline logic lives in `lib/pipeline/*`.
- **Concepts — the semantic scaffold** (`0017`): **`concepts`** (slug/name/short_definition/explanation + `status` `concept_status_t` settled/contested); **`concept_edges`** ("understand `prerequisite_id` before `concept_id`" — unique pair, no-self-loop CHECK, kept a **DAG** by the writer's in-transaction cycle walk in `lib/mutations/concepts.ts`); **`concept_claims`** (concept → claim/bridge by stable **text code**, resolved at read time like `signals.claim_touches`, dangling codes drift-flagged for admins). Both link tables carry `concept_link_status_t` (suggested/confirmed) so a future propose→queue flow needs no migration — today the app writes only `'confirmed'` (human-committed) rows and public reads filter on it. Seeded by `db:seed:concepts` (31 concepts, 51 edges; claim wiring is left to the admin). The last ten are transformer internals added for `/traceroute`, which links its 3D captions straight into these pages.
- Personal layer: `rationales` (append-only audit of confidence moves), `snapshots` (id→confidence JSON, for calibration), `positions_crosscutting` (+ `position_components`), source `reliability_prior`, `question_summaries` (per-question AI state summaries — `summary` + `metrics` JSON, newest-first).
- `snapshots` are auto-written (`post_commit`) inside `moveConfidence` on every confidence move and **read back by the `/calibration` viewer** (time-slider + trajectories + move log; `snapshotAction('manual')` is surfaced there as "Capture snapshot now").
- Still **scaffolded-but-unwired**: `extraction_queue` (we ship recommend-only, not a propose→queue→accept flow), `sources.storage_path` (PDF is text-only), and the **digest sender** (`/signals/digest` renders and `digest_snapshots` exists, but nothing writes/emails it). The `positions_crosscutting` editor is now **wired** via `/worldview`.

## Deploy (Vercel + Supabase)
- Connection precedence (`lib/db.ts`): if **`DATABASE_URL`** is set, use it; otherwise fall back to discrete **`SUPABASE_DB_*`** (direct). If neither is fully configured, `makePool()` throws. The `migrate`/`seed`/`verify` scripts always use `SUPABASE_DB_*` direct (DDL needs a session, not the transaction pooler).
- **Production MUST set `DATABASE_URL` to the Supabase POOLER (IPv4)**: `postgresql://postgres.<ref>:<pw>@aws-0-<region>.pooler.supabase.com:6543/postgres`. The direct `db.<ref>.supabase.co` host is **IPv6-only and unreachable from Vercel serverless**.
- **Pool size:** `lib/db.ts` defaults `DB_POOL_MAX` to **3** (`Number(process.env.DB_POOL_MAX || 3)`). When connecting through the transaction pooler, set `DB_POOL_MAX=1` (recommended in `.env.example`) so each serverless instance holds a single connection.
- **`AUTH_SECRET` required (≥ 32 chars)** or the app throws. Set a strong `ADMIN_PASSWORD`.
- **`ANTHROPIC_API_KEY` required for the AI features** (source dossier, PDF metadata, claim recommendations, lens recommendations, question-state summaries, media-landscape narration, Signal Board draft proposals, and the discovery pipeline's **web search**) — server-only; set it in Vercel Production and redeploy after changing it (env changes don't take effect until a redeploy).
- **`PORTAL_KEY` (optional)** unlocks the Datasets portal's billable features for colleagues (the team Ask + the full-text articles download); unset, those stay admin-only in practice while the catalog and other downloads remain public. `PORTAL_DAILY_BUDGET_USD` (default 1.00) and `PORTAL_DAILY_MAX_CALLS` (default 200) cap the portal Ask's daily spend, reset at midnight UTC.
- **`CRON_SECRET` (required for the cron-driven subsystems)**: authorizes every `/api/cron/*` route (scan, pipeline, intel, each with a `/sweep` sibling — six `vercel.json` entries; Vercel sends it as a Bearer header; the routes refuse everything when unset). `SCAN_DAILY_BUDGET_USD` (default 1.50) caps the scan's daily model spend; past the cap the run completes unenriched. **`TAVILY_API_KEY`** switches the scan's search leg to Tavily's free LLM-free news search (unset = the Sonnet web_search call); **`OPENROUTER_API_KEY`** powers the /scan picker's cheap enrichment models (unset or nothing picked = Haiku fallback).
- **Hosting is Vercel Pro since 2026-08-30** (was Hobby): up to 40 crons (each daily subsystem has its own path-keyed schedule now) and an 800s fluid-duration ceiling. The old "hard ~60s function cap" was already DEAD on Hobby (measured 2026-08-13: `maxDuration = 300` deploys and 290s streamed responses survive; the standing probe is `/api/probe/duration`, admin-gated; raw results in `docs/data-portal-upgrade-paths.md`). Most routes still declare `maxDuration = 60` and the DB-checkpointed engine decomposition remains good architecture (resumable, cheap retries); cron routes declare 300.
- **Never commit `.env.local`** (`.gitignore` allows only `.env.example`).

## Gotchas
- **Do NOT run `npm run build` while `npm run dev` is running** — it clobbers `.next` and 500s the dev server.
- **URL-encode `@` in a DB password as `%40`** inside any connection string (`DATABASE_URL`), or the URL parses wrong.
- `lib/db.ts` is server-only and throws in the browser — keep it out of `'use client'` files.
- After a schema change, add a new numbered file in `supabase/migrations/` (the runner skips already-applied files; it does not diff or re-run edited ones). Number it sequentially after the highest-numbered file already in that folder.
- **Function timeouts: measured, not assumed.** The codebase was built against a believed hard ~60s Vercel cap; on 2026-08-13 the probe (`/api/probe/duration`) proved ~300s works on this Hobby project (Fluid Compute era). Existing architecture keeps `maxDuration = 60` on most routes and the discovery pipeline stays **decomposed into many short, DB-checkpointed steps** (one lens batch, ≤3 searches ≈ 45s) because that buys resumability and cheap retries, not because the platform demands it. When a single longer function is genuinely simpler, declare `maxDuration` up to ~300 and keep the SDK timeout below it. `runStructured` (`lib/dossier.ts`) stays single and non-web for latency and cost reasons, not the old cap.
- **React Compiler lint rules are errors, with no opt-out** (`react-hooks/refs`, `set-state-in-effect`, `immutability`, `purity`, from `eslint-plugin-react-hooks@7` via `eslint-config-next`). Practical consequences: never read `ref.current` during render (resolve it in the handler or an effect), never `setState` synchronously in an effect body (use `useSyncExternalStore` or a callback), and keep mutation of external objects (a three.js scene) in module-scope functions called from effects. The repo's bar is a zero-warning run.
- **`three` geometry merging:** `mergeGeometries` refuses to mix indexed and non-indexed inputs, and `RoundedBoxGeometry` is non-indexed while `BoxGeometry`/`CylinderGeometry`/`TorusGeometry` are indexed. Normalise with `.toNonIndexed()` first. This failed silently once and dropped every detail feature on 20 objects. Also note core `LineDashedMaterial` has no `dashOffset` in 0.180.
- **`proxy.ts`'s matcher does not exclude `/api`.** A new public API route needs its own allow-list entry or it 307s to `/login`.
- **`signal_lens_t` ≠ `lens_t`.** The Signal Board's six audience lenses are a separate enum from the argument map's seven `lens_t` lenses — don't conflate them.
- **The pinned Anthropic SDK (0.100.1) stream accumulator predates server-tool blocks**: on
  a `messages.stream` call with `web_search`, `finalMessage().content` collapses to bare
  text blocks (no `server_tool_use`/`web_search_tool_result`, no citations). Capture web
  sources from the RAW `streamEvent`s instead (`content_block_start` of type
  `web_search_tool_result`, plus `citations_delta` when the model quotes) — the ask routes
  do exactly this. Re-check on any SDK upgrade.
- **`ai_cost_log.pipeline_run_id` is FK'd to `pipeline_runs`** — and `recordApiCall` swallows every insert error. A non-pipeline feature that passes its own run id there loses the cost row SILENTLY (and any budget guard summing that feature goes blind). Scan/scout calls carry provenance in `metadata` (`scan_run`/`scout_run`) and never set `pipelineRunId`.
- **`claude-haiku-4-5` rejects the `effort` parameter** (live-verified 2026-08-28: 400 "This model does not support the effort parameter"). `runStructured` therefore omits `thinking` + `output_config` whenever `opts.model` is set; keep that behavior if you touch it.
- **No em dashes in user-facing text.** Rendered UI strings use a comma/colon/period, ` · ` for label separators, and `–` (en dash) for null placeholders — never `—`. Every user-visible AI prompt (`dossier.ts`, `summary.ts`, `concepts.ts`, `report-generate.ts`, `tearsheet/generate.ts`, `pipeline/{analysis,triage,dedupe}.ts`) carries a "never use an em dash" instruction; keep it when editing prompts. (Code comments are exempt.)
